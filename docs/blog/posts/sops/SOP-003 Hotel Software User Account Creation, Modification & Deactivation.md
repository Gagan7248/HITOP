# HOTEL SOFTWARE USER ACCOUNT CREATION, MODIFICATION & DEACTIVATION

**Department:** Information Technology (IT)  
**SOP Category:** User Access & Identity Management  
**SOP Number:** SOP-003  
**Document Type:** Standard Operating Procedure  
**Applicable To:** All Hotel Departments Using IT Applications and Systems  
**Process Owner:** IT Department  
**Review Frequency:** Annually or whenever a major access control or system change occurs  
**Version:** 1.0  
**Effective Date:** As approved by hotel management

---

## 1. PURPOSE

The purpose of this Standard Operating Procedure is to establish a standardized process for creating, modifying, reviewing, and deactivating user accounts across hotel software applications and IT systems.

Hotels use multiple applications to manage daily operations, including Property Management Systems (PMS), Point of Sale (POS), accounting software, HR and payroll applications, email systems, attendance systems, CCTV platforms, and other business applications.

Proper user account management is essential to ensure that employees receive appropriate access according to their job responsibilities and that unauthorized access is prevented.

This SOP aims to:

- Establish a controlled user account management process.
    
- Ensure that employees receive access only to authorized systems.
    
- Maintain role-based access permissions.
    
- Prevent unauthorized account creation and privilege escalation.
    
- Ensure timely modification of access when employees change roles or departments.
    
- Ensure prompt deactivation of accounts when employees leave the organization.
    
- Maintain accurate user access records.
    
- Support information security, accountability, and audit requirements.
    

## 2. SCOPE

This SOP applies to all employees, authorized temporary staff, contractors, consultants, and third-party personnel who require access to hotel IT systems.

It covers user account management for:

- Property Management Systems (PMS).
    
- Point of Sale (POS) systems.
    
- Hotel accounting and financial applications.
    
- HR and payroll systems.
    
- Email and collaboration platforms.
    
- Attendance and biometric systems.
    
- CCTV and surveillance applications.
    
- Access control systems.
    
- Wi-Fi and network authentication.
    
- Server and workstation accounts.
    
- File sharing and document management platforms.
    
- Reservation and distribution systems.
    
- Engineering and maintenance applications.
    
- Other hotel-approved business applications.
    

This SOP applies to cloud-based, locally hosted, centrally managed, and third-party applications.

It covers the complete user access lifecycle:

1. New user account creation.
    
2. Existing user account modification.
    
3. Department or designation transfer.
    
4. Temporary access provisioning.
    
5. Privileged access management.
    
6. Periodic user access review.
    
7. Employee separation and account deactivation.
    
8. Access record maintenance.
    

## 3. RESPONSIBILITIES

### 3.1 IT Manager / IT Head

- Own the hotel-wide user account management process.
    
- Ensure that access requests follow the approved authorization process.
    
- Approve technical provisioning where designated by hotel policy.
    
- Ensure appropriate access controls are implemented.
    
- Review privileged and sensitive system accounts.
    
- Monitor account creation, modification, and deactivation activities.
    
- Coordinate with application vendors when necessary.
    
- Ensure access records are maintained for audit purposes.
    

### 3.2 IT Executive / IT Support Engineer

- Receive and verify approved access requests.
    
- Create, modify, and deactivate user accounts.
    
- Assign permissions according to approved roles.
    
- Maintain the user access register.
    
- Verify account functionality after changes.
    
- Report unauthorized or suspicious access requests.
    
- Escalate application-specific issues to vendors.
    
- Ensure access is removed within the required timeframe.
    

### 3.3 Human Resources Department

- Notify IT about new employee joining dates.
    
- Provide verified employee information.
    
- Inform IT about employee transfers, role changes, and separations.
    
- Confirm employee last working dates and access termination requirements.
    
- Coordinate with department heads to ensure timely access updates.
    

### 3.4 Department Head / Reporting Manager

- Request access for employees in their department.
    
- Identify the systems required for the employee's job.
    
- Recommend appropriate access roles and permissions.
    
- Approve access requests according to hotel policy.
    
- Notify IT about changes in employee responsibilities.
    
- Confirm when access is no longer required.
    
- Review departmental user access periodically.
    

### 3.5 Application Owner / System Administrator

- Define application-specific roles and permissions.
    
- Provide technical guidance for application access.
    
- Support role configuration and permission mapping.
    
- Verify sensitive application permissions.
    
- Assist IT during access reviews and investigations.
    

### 3.6 Employees / End Users

- Use only their assigned user accounts.
    
- Keep passwords and authentication credentials confidential.
    
- Avoid sharing accounts with colleagues.
    
- Report suspected unauthorized access immediately.
    
- Use applications only for authorized business purposes.
    
- Follow the hotel's IT security policies.
    

### 3.7 Third-Party Vendors

- Provide application-level access support when authorized.
    
- Create or modify accounts only under approved instructions.
    
- Restrict support access to the required duration and scope.
    
- Maintain confidentiality of hotel information.
    
- Remove temporary vendor access after the approved work is completed.
    

## 4. USER ACCOUNT CREATION PROCESS

User accounts must be created only after receiving a valid request from an authorized department representative.

### 4.1 Access Request Submission

1. The department head or authorized manager submits a formal access request to IT.
    
2. The request must contain the employee's full name.
    
3. Employee ID or another approved identification reference must be provided.
    
4. The department and designation must be specified.
    
5. The employee's joining date must be mentioned.
    
6. The required software applications must be identified.
    
7. The requested access role or permission level must be specified.
    
8. The request must be approved according to hotel policy.
    

### 4.2 Request Verification

Before creating an account, IT must:

1. Verify that the request comes from an authorized person.
    
2. Confirm the employee's identity and employment status.
    
3. Check whether the requested access is relevant to the employee's job.
    
4. Review whether an existing account is already assigned.
    
5. Confirm that the requested permission level is appropriate.
    
6. Verify all required approvals.
    
7. Return incomplete or unauthorized requests for correction.
    

### 4.3 Account Creation

After verification and approval:

1. Open the relevant application or user administration portal.
    
2. Navigate to the user management section.
    
3. Create a new user account.
    
4. Assign a unique username or user ID.
    
5. Enter the required employee information.
    
6. Assign the approved department, role, and access permissions.
    
7. Configure the approved authentication method.
    
8. Set a temporary password or initial login procedure where supported.
    
9. Enable multi-factor authentication where available and required.
    
10. Save the account configuration.
    
11. Verify that the account has been created successfully.
    
12. Record the account details in the user access register.
    

**Important:** Passwords must not be recorded in plain text in access registers, emails, spreadsheets, or other unsecured documents.

### 4.4 Initial Login Verification

1. Inform the employee through an approved communication channel that access is available.
    
2. Provide login instructions securely.
    
3. Ask the employee to complete the initial login.
    
4. Ensure that a temporary password is changed where applicable.
    
5. Verify that the employee can access the assigned application.
    
6. Confirm that unauthorized modules or functions are not accessible.
    
7. Record the account activation date.
    

## 5. ROLE-BASED ACCESS CONTROL

Access permissions must be assigned according to the employee's job responsibilities.

### 5.1 Access Level Classification

The hotel may define access levels such as:

|Access Level|Description|Example|
|---|---|---|
|Standard User|Basic operational access|Front Office Associate|
|Department Supervisor|Operational access with limited supervisory functions|Restaurant Supervisor|
|Department Manager|Department-level management access|F&B Manager|
|Finance / Sensitive User|Access to approved financial information and functions|Finance Executive|
|System Administrator|Technical configuration and user management access|Authorized IT Administrator|
|Read-Only User|View access without modification rights|Authorized Auditor|

Actual permissions must be defined separately for each application.

### 5.2 Least Privilege Principle

1. Provide only the access necessary for the employee's job.
    
2. Avoid granting administrator permissions for routine work.
    
3. Restrict financial and sensitive functions.
    
4. Separate operational and approval responsibilities where possible.
    
5. Do not assign permissions merely because another employee has them.
    
6. Review role assignments whenever job responsibilities change.
    

### 5.3 Administrator Account Control

- Restrict administrator accounts to authorized personnel.
    
- Use separate administrator and normal user accounts where supported.
    
- Avoid sharing administrator credentials.
    
- Protect privileged accounts with stronger authentication controls.
    
- Monitor privileged account activity.
    
- Review administrator access periodically.
    

## 6. USER ACCOUNT MODIFICATION PROCESS

User account modification is required when an employee's job responsibilities, department, designation, or access requirements change.

### 6.1 Modification Request

1. Receive a formal access modification request.
    
2. Verify the employee's identity and current department.
    
3. Confirm the employee's new designation or responsibilities.
    
4. Identify the existing access permissions.
    
5. Specify which permissions must be added, changed, or removed.
    
6. Obtain approval from the authorized department head.
    
7. Obtain additional approval for sensitive or privileged access where required.
    

### 6.2 Modification Procedure

1. Log in to the relevant application administration portal.
    
2. Locate the employee's existing account.
    
3. Review current permissions.
    
4. Remove access that is no longer required.
    
5. Add the newly approved permissions.
    
6. Modify the department or role information where necessary.
    
7. Verify that sensitive permissions remain restricted.
    
8. Save the changes.
    
9. Test the updated account functionality.
    
10. Update the user access register.
    
11. Notify the concerned department after completion.
    

### 6.3 Department Transfer

When an employee moves from one department to another:

1. Receive official transfer information from HR or the authorized department.
    
2. Confirm the effective transfer date.
    
3. Review access granted under the previous department.
    
4. Remove access that is no longer required.
    
5. Obtain approval for new departmental access.
    
6. Assign the permissions required for the new role.
    
7. Verify the updated access.
    
8. Record the changes and effective date.
    

**Important:** Previous departmental access must not remain active automatically unless it is still required and specifically approved.

## 7. TEMPORARY AND THIRD-PARTY USER ACCESS

Temporary accounts may be required for contractors, consultants, auditors, technical vendors, or temporary employees.

### 7.1 Temporary Access Request

1. Receive a formal request from the responsible department.
    
2. Verify the identity of the external or temporary user.
    
3. Record the organization and purpose of access.
    
4. Identify the required application and permissions.
    
5. Specify the start and expiry dates.
    
6. Obtain approval from the authorized department head and system owner where required.
    

### 7.2 Temporary Account Creation

1. Create a unique account wherever technically supported.
    
2. Assign only the minimum required permissions.
    
3. Set an expiry date or scheduled deactivation where available.
    
4. Enable appropriate authentication controls.
    
5. Restrict access to approved systems and resources.
    
6. Record the account owner and expiry date.
    
7. Inform the responsible department when access is activated.
    

### 7.3 Temporary Account Closure

1. Confirm that the approved work has been completed.
    
2. Verify the expiry date.
    
3. Disable or remove the account.
    
4. Revoke associated access tokens or credentials where applicable.
    
5. Update the access register.
    
6. Confirm closure with the responsible department.
    

Temporary accounts must not remain active indefinitely.

## 8. PASSWORD AND AUTHENTICATION MANAGEMENT

### 8.1 Password Policy

All users must follow the hotel's approved password policy.

The policy should define:

- Minimum password length.
    
- Password complexity requirements where appropriate.
    
- Password reuse restrictions.
    
- Password reset procedures.
    
- Account lockout controls.
    
- Multi-factor authentication requirements.
    
- Password recovery and identity verification procedures.
    

Passwords should be unique and difficult to guess. Multi-factor authentication should be enabled for sensitive systems and privileged accounts wherever supported.

### 8.2 Password Reset Procedure

1. Receive the password reset request from the employee.
    
2. Verify the employee's identity using an approved method.
    
3. Confirm that the requester is the legitimate account owner.
    
4. Reset the password through the authorized administration process.
    
5. Provide temporary credentials through a secure communication channel.
    
6. Require a password change at the next login where supported.
    
7. Record the reset activity without recording the actual password.
    
8. Escalate suspicious or repeated reset requests.
    

### 8.3 Account Lockout

If an account is locked:

1. Verify the employee's identity.
    
2. Check whether the lockout resulted from repeated failed login attempts.
    
3. Review security alerts where available.
    
4. Unlock the account only after appropriate verification.
    
5. Reset credentials if compromise is suspected.
    
6. Document the incident.
    
7. Escalate suspicious activity to the IT Manager.
    

## 9. EMPLOYEE SEPARATION AND ACCOUNT DEACTIVATION

Account deactivation is a critical security activity and must be completed promptly when an employee leaves the hotel or no longer requires access.

### 9.1 Separation Notification

1. Receive official employee separation information from HR.
    
2. Verify the employee's full name and employee ID.
    
3. Confirm the last working date and effective termination time.
    
4. Identify all applications and systems accessed by the employee.
    
5. Identify any privileged or administrator accounts.
    
6. Confirm whether immediate access suspension is required.
    

### 9.2 Account Deactivation Procedure

On the approved effective date and time:

1. Access the relevant user administration portal.
    
2. Locate the employee's account.
    
3. Disable or deactivate the account.
    
4. Revoke active sessions where supported.
    
5. Revoke associated authentication tokens and application access where applicable.
    
6. Disable email, VPN, and network access according to hotel policy.
    
7. Remove access to shared folders and business applications where authorized.
    
8. Revoke privileged access.
    
9. Review any assigned temporary or shared access that requires reassignment.
    
10. Record the account deactivation date and time.
    
11. Update the user access register.
    
12. Notify HR or the authorized department that the process is complete.
    

### 9.3 Immediate Access Suspension

If an employee is terminated with immediate effect, suspected of unauthorized activity, or involved in a security incident:

1. Follow the instructions of HR and authorized management.
    
2. Suspend access immediately when directed.
    
3. Coordinate deactivation across all relevant applications.
    
4. Preserve required audit logs and records.
    
5. Avoid deleting user data or business records without authorization.
    
6. Escalate any suspected security incident through the established incident management process.
    

### 9.4 Data and Account Ownership

Before closing an employee's account, IT must coordinate with HR, the department head, and relevant system owners regarding:

- Business email and mailbox retention.
    
- Ownership of business files.
    
- Shared folders and documents.
    
- Pending approvals or workflows.
    
- Application records and transaction history.
    
- Assigned devices and system credentials.
    
- Transfer of business responsibilities.
    

Account deactivation must not result in unauthorized deletion of business information.

## 10. PERIODIC USER ACCESS REVIEW

The IT Department should conduct periodic reviews to ensure that active user accounts remain appropriate.

### 10.1 Review Procedure

1. Generate a list of active users from each relevant application.
    
2. Compare the list with current HR employee records.
    
3. Identify inactive, duplicate, obsolete, and unnecessary accounts.
    
4. Identify users with excessive permissions.
    
5. Review administrator and privileged accounts separately.
    
6. Share departmental user lists with authorized department heads.
    
7. Obtain confirmation of required access.
    
8. Modify or deactivate accounts based on approved instructions.
    
9. Record the review results.
    
10. Escalate unresolved access discrepancies.
    

### 10.2 Recommended Review Frequency

|Account Type|Recommended Review Frequency|
|---|---|
|Standard User Accounts|Quarterly|
|Department Manager Accounts|Quarterly|
|Administrator Accounts|Monthly or Quarterly|
|Third-Party Accounts|Monthly and at expiry|
|Temporary Accounts|At expiry or project completion|
|Dormant Accounts|Monthly or as per security policy|
|Sensitive Financial Accounts|Quarterly or as required by policy|

The final review frequency should be based on system sensitivity, risk, legal requirements, and hotel policy.

## 11. PRIVILEGED AND SENSITIVE ACCESS MANAGEMENT

Privileged access allows users to perform administrative or sensitive operations and must be tightly controlled.

### 11.1 Privileged Access Request

1. Receive a formal request.
    
2. Identify the business or technical requirement.
    
3. Confirm why standard access is insufficient.
    
4. Obtain approval from the designated authority.
    
5. Assign the minimum required privileged permissions.
    
6. Define the access duration where possible.
    
7. Record the approval and account details.
    

### 11.2 Privileged Access Monitoring

- Maintain a separate list of privileged accounts.
    
- Restrict administrator access to authorized personnel.
    
- Use multi-factor authentication wherever supported.
    
- Review privileged account activity.
    
- Avoid using administrator accounts for routine tasks.
    
- Remove temporary privileged access after completion.
    
- Investigate unexpected privilege changes.
    

## 12. DORMANT AND UNUSED ACCOUNT MANAGEMENT

Unused accounts can create unnecessary security risks.

### 12.1 Identification

1. Review application login reports or account activity logs where available.
    
2. Identify accounts that have not been used for the period defined in hotel policy.
    
3. Compare dormant accounts with current HR records.
    
4. Identify accounts belonging to transferred or separated employees.
    
5. Identify unused temporary and vendor accounts.
    

### 12.2 Deactivation

1. Verify whether the account is still required.
    
2. Obtain confirmation from the relevant department or system owner.
    
3. Disable unnecessary accounts.
    
4. Preserve business records and audit logs.
    
5. Record the deactivation activity.
    

Service accounts, integration accounts, and emergency accounts must not be disabled solely because they show no regular interactive login activity. Their ownership and purpose must be verified first.

## 13. USER ACCOUNT SECURITY CONTROLS

The IT Department must maintain appropriate security controls across the user account lifecycle.

### 13.1 General Security Controls

- Every employee must use an individually assigned account wherever supported.
    
- Shared accounts should be avoided.
    
- Access must be based on job responsibilities.
    
- Administrator permissions must be restricted.
    
- Passwords must not be shared.
    
- Multi-factor authentication should be used for sensitive systems.
    
- Accounts must be deactivated promptly after separation.
    
- Temporary accounts must have defined expiry dates.
    
- Access changes must have documented authorization.
    
- Suspicious login activity must be investigated.
    

### 13.2 Application-Specific Controls

Different hotel applications may have different permission structures.

Examples include:

- PMS access to guest profiles and reservations.
    
- POS access to order entry, billing, and financial adjustments.
    
- Accounting access to financial reports and transactions.
    
- HR access to employee information.
    
- CCTV access to live viewing and recorded footage.
    
- Attendance access to employee attendance records.
    

Each application owner must define the appropriate roles and permissions for the relevant system.

## 14. VENDOR AND APPLICATION SUPPORT COORDINATION

Some hotel applications require vendor assistance for account management or permission configuration.

### 14.1 Vendor Request Process

1. Identify the application and access issue.
    
2. Verify the required change and approval.
    
3. Create a vendor support ticket where necessary.
    
4. Provide only the information required to complete the request.
    
5. Avoid sharing employee passwords or unnecessary personal information.
    
6. Monitor the vendor request.
    
7. Verify the completed change.
    
8. Update the user access register.
    

### 14.2 Vendor Access Control

- Vendor access must be formally authorized.
    
- Access must be limited to the required system and activity.
    
- Temporary access must have a defined duration.
    
- Vendor accounts must be reviewed periodically.
    
- Access must be removed after the support activity or contract ends.
    
- Vendor activity should be logged where supported.
    

## 15. USER ACCESS DOCUMENTATION AND RECORD MANAGEMENT

The IT Department must maintain accurate records of all user account management activities.

Required records may include:

1. User Account Creation Request Register.
    
2. User Account Modification Register.
    
3. User Account Deactivation Register.
    
4. User Access Master Register.
    
5. Department-Wise User Access List.
    
6. Privileged Account Register.
    
7. Temporary and Vendor Access Register.
    
8. Password Reset Activity Register.
    
9. Periodic User Access Review Records.
    
10. Employee Separation Access Checklist.
    
11. Access Approval Records.
    
12. Security Incident and Investigation Records.
    

### 15.1 User Access Register – Recommended Fields

|Field|Description|
|---|---|
|Employee Name|Full employee name|
|Employee ID|Unique employee reference|
|Department|Employee's department|
|Designation|Current job title|
|Application Name|Software or system name|
|Username|Assigned account ID|
|Access Role|Approved role or permission level|
|Request Date|Date of access request|
|Approval Authority|Authorized approver|
|Account Creation Date|Date account was created|
|Modification Date|Date of latest access change|
|Deactivation Date|Date account was disabled|
|Account Status|Active / Disabled / Expired|

**Security Note:** Do not include passwords, authentication codes, recovery codes, or other secrets in this register.

All records must be stored in an access-controlled location and retained according to hotel policy.

## 16. USER ACCOUNT MANAGEMENT ESCALATION MATRIX

|Priority|Issue|Initial Action|Escalation|
|---|---|---|---|
|Critical|Suspected unauthorized administrator access|Immediately restrict access according to incident procedure|IT Manager, Security Team, Management|
|Critical|Separated employee account remains active|Immediate verification and deactivation|IT Manager, HR|
|High|Unauthorized access to sensitive financial or guest information|Restrict access and preserve logs|IT Manager, System Owner, Management|
|High|Incorrect permissions affecting business operations|Review and correct approved access|IT Manager, Department Head|
|Medium|New user account creation delay|Verify request and approvals|IT Support / Department Head|
|Medium|User account modification issue|Review application permissions|IT Support / Application Vendor|
|Low|Routine password reset|Verify identity and process reset|IT Support|
|Low|General access information request|Follow standard support process|IT Helpdesk|

Actual response and resolution times must follow the hotel's approved IT service levels.

## 17. USER ACCOUNT MANAGEMENT PERFORMANCE MONITORING

The IT Manager should periodically review the following performance indicators:

- Number of new user accounts created.
    
- Number of user account modifications.
    
- Number of accounts deactivated.
    
- Percentage of employee separations processed within the required timeframe.
    
- Number of unauthorized access attempts.
    
- Number of dormant accounts identified.
    
- Number of accounts with excessive permissions.
    
- Number of overdue access review actions.
    
- Number of temporary accounts exceeding expiry dates.
    
- Average time required to process approved access requests.
    
- Number of unresolved access management incidents.
    

These indicators should be used to improve access management efficiency and reduce security risks.

- Confirm department and designation.
    
- Identify required applications.
    
- Verify approval from the authorized department head.
    
- Assign an individual username.
    
- Apply approved role-based permissions.
    
- Configure secure authentication.
    
- Verify account functionality.
    
- Update the user access register.
    
- Inform the concerned department.
    

### 18.2 User Account Modification Checklist

- Verify employee details.
    
- Confirm revised job responsibilities.
    
- Review existing permissions.
    
- Remove unnecessary permissions.
    
- Add approved new permissions.
    
- Verify the updated account.
    
- Update the access register.
    
- Inform the concerned department.
    

### 18.3 Employee Separation / Account Deactivation Checklist

- Receive official HR separation notification.
    
- Verify employee name and ID.
    
- Confirm the effective date and time.

## 20. COMPLIANCE AND EXCEPTIONS

All departments and employees must comply with this SOP.

Any exception to the standard user account management process must:

- Have a valid business or technical reason.
    
- Be documented formally.
    
- Be reviewed by the relevant department head.
    
- Be approved by the authorized management representative.
    
- Be recorded by IT.
    
- Have an expiry date or review date wherever appropriate.
    

Unauthorized account creation, credential sharing, privilege misuse, or failure to deactivate access after employee separation must be reported through the hotel's established IT security incident process.
